# Step 11：Google Maps 頁面實測與選擇器

## 狀態與範圍

- 狀態：已規劃，尚未實作。
- 計畫日期：2026-11-24（Asia/Taipei）。
- 所屬階段：階段三；前置條件：Step 7–10。
- 依據：[spec.md](../spec.md)、[implementation.md](../implementation.md) 及 [agent.md](../agent.md)。

確認真實 Maps 各種頁面的定位方式，集中保存經驗證的選擇器；不開始大量擷取。

## 實作流程

**輸入：**少量可公開存取的地點與短網址樣本。

**要做的事：**

1. 使用受管理的 session 驗證短網址可定位預期地點，記錄 URL、地點標題與必要定位證據。
2. 檢查搜尋列表、詳細頁、評論、照片介面的主要容器與操作元素，記錄定位條件及等待狀態。
3. 檢查結果列表或評論可能提供的識別資訊，供後續頁面去重使用；尚未確認的項目標記待驗證，不捏造選擇器。
4. 在 `selectors.py` 依頁面用途集中管理已驗證的定位條件，記錄驗證日期、語言及環境。
5. 此步只確認操作基礎，不開始批次抓取，也不將 URL 變化當作地點身分變化。

**完成條件：**有可查閱的實測紀錄及定位條件。若真實頁面無法存取，完成不受影響的離線工作並明列未驗證範圍，不宣稱整個階段已通過實測。

## 預計檔案

`selectors.py`、Maps opt-in 整合測試、樣本與定位紀錄、相關文件。

## 測試方式

使用少量公開頁面，在真實 Chrome 驗證搜尋、詳細資料、評論與照片容器，記錄日期、語言、瀏覽器／driver 版本及頁面證據。

瀏覽器操作有變更時，假物件測試不能替代實際測試。整合測試使用明確 opt-in 開關，實作時記錄命令、環境與結果；無法執行須明列原因，不標記該項完成。

## 驗收條件

- [ ] 主要容器及操作定位條件經真實 Maps 驗證。
- [ ] 短網址可定位預期地點，已確認項目識別資訊。
- [ ] 登入、驗證或無法存取時明確記錄，不捏造選擇器。
- [ ] 樣本限制與尚未驗證項目如實記錄。
