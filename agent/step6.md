# Step 6：階段二地點比對與 ID 沿用計畫

## 狀態與目標

- 狀態：已完成，2026-11-24（Asia/Taipei）。
- 更新日期：2026-11-24（Asia/Taipei）。
- 所屬階段：[implementation.md](../implementation.md) 的階段二。
- 前置條件：階段一的資料模型、例外及 UUID 工具已完成。
- 規則依據：[spec.md](../spec.md)；紀錄方式依 [agent.md](../agent.md)。

本階段要解決的問題是：取得一筆新地點資料後，如何判斷它是否對應到既有地點，並讓相關資料使用同一個 ID。

整體流程為：

> 收到新資料與既有候選 → 逐筆計算差異 → 排除差異超過兩欄的候選 → 選出差異最少的一筆 → 沿用該筆 ID → 回傳更新 ID 後的資料副本。

「候選」是呼叫端提供的一筆既有地點紀錄。「呼叫端」是使用本套件的程式，負責取得既有資料與保存結果。本套件只處理記憶體中的資料，不查詢或寫入資料庫。

## 1. 本階段要提供的三個工具

以下為本步驟採用的介面，已先同步至規格，再依序實作與驗證。

| 工具 | 要完成的事情 | 回傳結果 |
|---|---|---|
| `compare_places(existing, incoming)` | 比較一筆既有紀錄與一筆新詳細資料 | `PlaceComparison`，列出比較了哪些欄位、哪些不同，以及差異數 |
| `find_place_match(incoming, candidates)` | 比較全部候選，選出符合規則且差異最少的一筆 | 唯一最佳結果；沒有符合者回傳 `None`；最低差異並列時拋出錯誤 |
| `rebind_location_id(record, location_id)` | 將已確認的地點 ID 套用到資料 | 使用目標 ID 的新模型，原物件不變 |

這三個工具分開使用：比對工具負責提供判斷結果；呼叫端確認要沿用的 ID 後，再呼叫 ID 套用工具。比對不會自動更新欄位或保存資料。

## 2. 實作順序

### 步驟一：確認輸入與可比較的欄位

**輸入：**一筆新 `PlaceDetail`，以及一筆或多筆既有地點紀錄。

**要做的事：**

1. 新資料必須是 `PlaceDetail`；搜尋列表的 `PlaceSearchResult` 資料不足，不能直接用來做完整比對。
2. 既有紀錄接受 `PlaceDetail`，也接受使用相同欄位名稱的字典或 mapping。mapping 是可用欄位名稱取值的資料，例如資料庫查詢後取得的字典。
3. 既有紀錄必須有合法的 UUID v4 `location_id`，否則無法沿用 ID，應回報輸入錯誤。
4. 從目前 `PlaceDetail` 的欄位中排除 `location_id`、`fetched_at`，其餘欄位可參與比對。資料庫額外的 `_id`、狀態或操作紀錄不比較。
5. 允許歷史紀錄缺少欄位，不先補預設值或強迫轉成完整模型。非空欄位若型別錯誤，回報 `InvalidInputError` 或其明確子類，不靜默改值。

**完成條件：**能區分欄位缺漏、欄位為空與型別錯誤，且不修改輸入資料。未來 `PlaceDetail` 新增欄位時，同樣依這套欄位列舉方式處理。

### 步驟二：實作一對一欄位比較

**輸入：**一筆有效既有紀錄 `existing`，以及新詳細資料 `incoming`。

**要做的事：**

1. 依 `PlaceDetail` 的欄位順序檢查既有紀錄。
2. 既有欄位若不存在、是 `None`、空字串、只有空白的字串或空清單，就跳過該欄位；數值 `0` 不跳過。
3. 對每個沒有跳過的欄位，比較新舊值。新值缺漏、為空或不同，都計為一個不同欄位。
4. 清單必須內容與順序都相同；即使清單內有多個項目改變，也只算該欄位不同一次。
5. 比完所有欄位，再計算差異數。差異不超過兩欄就符合，三欄以上不符合。
6. `maps_url`、`rating`、`photos` 也照常比較。名稱、URL 或 ID 相同，都不能直接略過整個比較流程。

**回傳：**不可變的 `PlaceComparison`，包含下列資訊。結果只保存 ID 與欄位名稱，不保留會隨輸入修改而變動的原始物件參照。

| 欄位／屬性 | 意義 |
|---|---|
| `existing_location_id` | 被比較的既有地點 ID |
| `compared_fields` | 實際參與比較的欄位名稱，以 tuple 保存 |
| `different_fields` | 值不同或新資料缺漏的欄位名稱，以 tuple 保存 |
| `difference_count` | `different_fields` 的數量，不另外保存另一份計數 |
| `is_match` | `difference_count <= 2` 的結果 |

**例子：**

| 既有資料 | 新資料 | 怎麼計算 |
|---|---|---|
| 電話有值 | 電話改變 | 差異加一 |
| 網站有值 | 網站為 `None` | 差異加一 |
| 營業時間缺漏 | 補上營業時間 | 不計差異 |
| 照片清單有值 | 相同照片、順序改變 | 差異加一 |
| 評分為 `0` | 評分為 `None` | 差異加一 |

**完成條件：**完整列出差異，不能超過兩欄就提早停止。新資料補上的欄位不增加當次差異；但保存後，該欄位會成為下一次比較的既有基準。

### 步驟三：從多筆候選中選出最佳結果

**輸入：**一筆新 `PlaceDetail`，以及既有候選集合。集合可以是列表，也可以是只能讀取一次的 iterable。

**要做的事：**

1. 對每筆候選呼叫 `compare_places()`。
2. 讀完全部候選。遇到第一筆符合、零差異或暫時並列時，都不要立即結束。
3. 排除差異超過兩欄的候選。
4. 若全部被排除，回傳 `None`；呼叫端保留新資料原先配置的 ID，不重新產生 ID。
5. 若還有候選，找出最低的差異數，只看差異欄位的個數，不改用比例或權重。
6. 最低差異數只有一筆時，回傳該筆 `PlaceComparison`，供呼叫端沿用它的 ID。
7. 最低差異數有多筆時，拋出 `AmbiguousPlaceMatchError`，並提供並列候選的 ID 與差異資訊。

| 各候選的差異數 | 預期處理 |
|---|---|
| `0, 1, 2` | 選擇差異為 `0` 的那一筆 |
| `1, 2` | 選擇差異為 `1` 的那一筆 |
| `1, 1, 2` | 最低差異 `1` 並列，拋出錯誤 |
| `0, 0, 1` | 最低差異 `0` 並列，拋出錯誤 |
| `1, 1, 0` | 選擇最後的零差異候選，不因前面的並列提前失敗 |
| `3, 4` | 都不符合，回傳 `None` |

**完成條件：**更換候選順序不影響結果。不合法候選要回報輸入錯誤，不能跳過後宣稱已找出唯一最佳結果。重複候選不自行去重；若因此並列最低差異，仍回報歧義，由呼叫端清理候選。

### 步驟四：將選定的 ID 套用到資料副本

**輸入：**呼叫端確認的目標 ID，以及五種資料模型中的任一個物件。

**要做的事：**

1. 驗證目標 ID 是合法 UUID v4。
2. 建立與輸入相同具體型別的新模型，只改 `location_id`。
3. 保留其他欄位、清單順序及 `fetched_at`；這是關聯更新，不是重新擷取。
4. 複製清單容器，使回傳資料的清單修改不會影響原物件。目標 ID 與原 ID 相同時，也回傳副本。
5. 若輸入是 `ReviewSummary`，先建立使用新 ID 的每則評論與標籤副本，再使用這些副本建立新摘要。評論的照片清單也要獨立。
6. 完成全部建構與驗證後才回傳，任何失敗都不修改原資料。

**完成條件：**搜尋結果、詳細資料、摘要、評論與標籤可使用相同 ID，所有副本保留原始擷取時間。工具不會自行判斷地點是否相同，應只在呼叫端確認關聯後使用。

呼叫端若同時持有搜尋結果、詳細資料與摘要，先準備三者的副本，再一起替換自己的參照。也可以先比對詳細資料，決定 ID 後再抓評論，減少事後更新。

## 4. 測試清單

| 情境 | 必須驗證的結果 |
|---|---|
| 差異為 0、1、2、3 欄 | 前三者符合；三欄不符合；都列出完整差異 |
| 既有欄位缺漏或為空 | 不當作比較基準；數值 `0` 仍參與 |
| 新資料缺少既有非空欄位 | 該欄位算一次差異 |
| 新資料補上欄位 | 當次不增加差異；保存後會參與下一次比對 |
| ID、時間與資料庫額外欄位改變 | 不影響差異數 |
| 網址、評分、照片改變 | 照常計算差異 |
| 清單換序或多項改變 | 每個清單欄位最多計一次差異 |
| 候選為空或全部超過兩欄差異 | 回傳 `None`，保留新 ID |
| 多筆符合 | 選出差異唯一最少者；只在最低差異並列時拋出錯誤 |
| 改變候選順序 | 選擇結果不變；先並列後出現較佳者仍可成功 |
| 一次性 iterable、重複候選 | 不漏讀；不自行去重；重複最佳候選仍回報歧義 |
| 搜尋結果代替詳細資料、無效 ID 或欄位型別 | 明確回報輸入錯誤 |
| 五種模型重新套用 ID | 型別與非 ID 資料保留；摘要及所有子物件使用同一 ID |
| 修改回傳副本或其清單 | 不改變原模型；失敗也不留下部分修改 |
| 既有有效欄位只有 0–2 欄 | 依現行規則可能全部不同仍符合，保留此已知風險測試 |
| 公開匯入、範例與乾淨安裝 | 可離線執行，不啟動瀏覽器或存取資料庫 |

## 6. 本階段保留的限制

現行規則不保證地點辨識正確率。既有資料很少的候選可能得到較低差異數而勝出；網址、評分與照片同時更新，也可能讓同一地點超過兩欄差異。

初版維持直接比較，不加入最低有效欄位數、文字正規化、權重、欄位覆蓋率、座標或 Plus Code。這些項目留待收集樣本後評估。

比較以既有資料為基準，反過來比較可能得到不同結果；A 與 B、B 與 C 分別符合，也不能直接推論 A 與 C 相同。本階段不做批次串接合併、資料庫候選查詢、索引或欄位更新策略。
