## 實作流程

**要做的事：**

1. 以假 driver、假時鐘與模擬 HTTP 回應驗證邏輯，不讓一般單元測試連線或等待真實秒數。
2. 使用本機 HTML 測試動態元素、可點擊狀態、列表替換與捲動，再執行步驟七的受控 Maps 實測。
3. 實際瀏覽器與外部網路測試使用明確的 integration 標記及 opt-in 開關；預設測試維持離線，已有 196 項測試不得退化。
4. 建置 sdist／wheel，在乾淨環境安裝並從專案目錄外檢查匯入、設定及 URL／操作工具。
5. 即使 Selenium 已安裝，匯入套件、建立設定或只使用模型與比對時，也不能啟動瀏覽器或下載 driver。
6. 更新公開文件，說明 Chrome、driver 取得方式、實際驗證版本、需要網路的時機與工具設定。
7. 將命令、結果、未驗證情境及限制寫回本文件，通過驗收後再更新索引。

**完成條件：**離線測試、瀏覽器測試與外部實測各有獨立結果；建置安裝成功，且不將跳過或無法執行的測試當作通過。

## 預計檔案

整合測試、範例、安裝文件、必要建置設定、本文件及階段進度。

## 測試方式

執行所有離線測試、本機 Chrome 測試與受控 Maps 實測；建置 sdist／wheel 後，在乾淨環境及專案目錄外驗證，記錄測試版本。

瀏覽器操作有變更時，假物件測試不能替代實際測試。整合測試使用明確 opt-in 開關，實作時記錄命令、環境與結果；無法執行須明列原因，不標記該項完成。
