## 實作流程

**輸入：**捲動容器、讀取項目的函式、取得項目識別值的函式，以及數量與輪數上限。

**要做的事：**

1. 先讀取目前項目，以呼叫端提供的識別值追蹤已取得內容，保留首次取得順序。識別值不能使用每次重新產生的隨機 UUID。
2. 捲動後以條件等待檢查是否出現新識別值，不只看 DOM 元素數量或捲動高度，因為列表可能替換已顯示的元素。
3. 確認容器仍正常載入、但本輪等待內沒有新項目時，才將無新增計數加一；有新增就歸零。
4. 遇到數量上限、明確結尾標記或連續無新增達門檻時正常停止。建議無新增門檻預設三輪，可調整。
5. 另外設定最大捲動輪數，建議預設 100 輪；若觸及此保護上限，明確回報上限錯誤，不宣稱已到列表結尾。
6. 容器遺失、頁面失效或必要內容無法載入時回報操作錯誤，不將這些失敗算作正常無新增。
7. 回傳項目與正常停止原因；各頁面的識別值選擇由後續爬取流程接上，不在此步套用完整地點比對。

**完成條件：**相同 DOM 數量仍能取得新項目；重複內容不新增；正常無進展可以停止，頁面故障與保護上限不會變成成功空結果。

## 預計檔案

`interaction.py`、捲動單元測試、本機虛擬列表 fixtures、Chrome 整合測試、規格與文件。

## 測試方式

模擬新增、重複及錯誤情境，並以真實 Chrome 操作本機動態／虛擬列表，確認 DOM 數量固定時仍能辨識新內容，正常停止與故障清楚區分。

瀏覽器操作有變更時，假物件測試不能替代實際測試。整合測試使用明確 opt-in 開關，實作時記錄命令、環境與結果；無法執行須明列原因，不標記該項完成。

## 驗收條件

- [ ] 使用穩定項目識別值，保留首次取得順序。
- [ ] 數量上限、結尾與連續無新增正常停止，回傳停止原因。
- [ ] 容器故障與最大輪數保護明確失敗，不宣稱列表已完整取得。
- [ ] 實際 Chrome 的捲動與列表替換測試通過。
